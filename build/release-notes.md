## 新功能
- 反代网关 · 跨渠道故障转移（Failover + Failback）：渠道报 503/429 或号池耗尽时，请求内自动跳到其他渠道继续用（按余额充足度排序选备选），客户端完全无感；连续 2 次「真实尝试后打光」才把整个渠道降级（默认 120 秒），降级期内所有新请求（含指定路由的 Key）直接走备选渠道不再撞墙
- 降级到期自动半开回切：流量自动回到恢复且余额最充足的渠道；回切后再失败退避时长翻倍（120s → 240s → 480s → 封顶 15 分钟），防止上游未恢复时在两个渠道间反复横跳；请求成功一次即清零退避状态
- 渠道耗尽/降级后所有渠道仍不可用时，错误信息带完整轨迹（如「N 个渠道均不可用（trae→workbuddy_ai→zcode）」）；成功请求的流水备注记录切换轨迹（如 failover:trae→workbuddy_ai）
- 号池页渠道卡新增降级徽标（剩余秒数倒计时 + 悬停看原因）；渠道降级/恢复实时事件推送
- 设置页「服务与路由」新增故障转移配置组：总开关、单请求最多尝试渠道数（默认 3）、降级基础时长与封顶（失败翻倍）

## 修复
- 渠道级 WAF 拦截 / 白名单 11128 从「固定 60 秒 + 直接报错」升级为「指数退避 + 自动跳备选渠道」，不再白白失败一笔请求
- 跨渠道跳转时按渠道重算反向模型映射（此前换渠道沿用第一个渠道的目标模型名会打错模型）
- 纯本地打光（全冷却/耗尽/模型级负缓存）不再降级渠道：号池状态是实时派生的，渠道级再缓存一份会把已恢复的渠道错误地挡在门外（自测回归中实测发现并根治）
- 反代网关 · 小浣熊渠道中文标题崩溃根治：会话标题（取首条用户消息）含中文时 HTTP 头校验直接失败，请求根本没发出去、账号还被误罚冷却（此前表现为「渠道冷却 / 池中无可用账号」）——非 ASCII 字符现在自动转码，中文会话不再触发
- 反代网关 · 长回答 30 秒被掐断根治：小浣熊 / ZCode 渠道的「首字节 30 秒超时」定时器此前在整个回答期间一直挂着，超过 30 秒的回答会被中途砍断——现在首字节到达即解除，长回答完整跑完
- 反代网关 · usage 扩展字段透传补齐（WorkBuddy / 小浣熊 / ZCode 三渠道）：保留上游返回的缓存命中 token 数、单次积分消耗（credit）等扩展字段，下游客户端的缓存命中率恢复正常显示；账号余额随用量的实时扣减对这三条渠道真正生效
- 反代网关 · BigModel 系账号 coding-plan 凭据识别放宽：此前只认 zai- 家族键名 + UUID 账号 ID，BigModel 系账号的 coding-plan key 会被静默丢弃、对话只能退回备用通道——现在按实际键名形态放宽，重新导入账号即可走 coding-plan 通道

## 说明
- 本版合并上游 v1.40.0 + v1.40.1。故障转移的备选只从**内置渠道**里挑：自定义提供商（`标识/模型` 前缀直达那类）不参与跳渠道，不会把用户自己的中转静默改投别家渠道

- v1.40.1 的修复源自社区贡献者 zhuchiheng 的 PR #18 / #19（均附实测数据），经复核后合并；usage 透传以本 fork 的 normalizeOpenAiUsage 统一收口（cache/credit 归一已覆盖 PR 目标字段），无破坏性变更，装完即生效
